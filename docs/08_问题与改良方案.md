## 二、问题清单（按严重程度排序）

### P0-1 趴桌睡觉 / 玩手机：数据量天花板，且全部来自外校

- **证据**：趴桌睡觉 3,004 框（1,121 图）、玩手机 8,527 框（1,215 图），仅占全量 392,695 框的 **2.9%**；
  这两类的公开数据全网只有 Roboflow（海外教室）+ SCB-Dataset3 高校子集（671 张）两份，检索记录见 `docs/07`。
- **后果**：mAP50 0.51 / 0.69 看着还行，但 mAP50-95 只有 0.19 / 0.23（框位置不准），换到本校教室会进一步掉。
- **改良**：自采本校数据，趴桌、玩手机各 200~300 张；这两类是唯一"数据量决定上限"的类。

### P0-2 阅读看书 / 小组讨论：标注口径不一致，模型学不到稳定特征

- **证据**：阅读 mAP50 0.340、讨论 mAP50 0.325，是全表最弱两类；且多来源框大小差异明显——
  SCB5 的 discuss 框平均 **0.214×0.291**（一组人），STBD-08 的 discuss 框平均 **0.152×0.154**（单人），
  同一类别两种标注习惯混在一起训练。
- **后果**：模型对"讨论"的定位模糊，误检集中在同桌区域。
- **改良**：① 统一标注规范（一人一框，禁止组框）；② 对历史数据按框面积做一次清洗（框面积 > 均值 2σ 的组框剔除或拆分）；
  ③ 补标时严格按 `docs/02_八类定义与标注规范.md` 执行。

### P0-3 小目标：后排学生只有几十像素，mAP50-95 被拉低

- **证据**：mAP50（0.540）与 mAP50-95（0.362）差距 0.18，典型的"能检出但框不准"。
- **原因**：640×640 输入下，后排一个人约占 30~50 像素；框偏 5~10 像素，IoU 就从 0.8 掉到 0.5。
- **改良**：imgsz 640 → 896 微调（经验 +2~4 mAP，代价训练时长 ×2），或对整班大图做切片推理（tile 640 + 20% 重叠）。

### P1-1 相似类混淆：阅读 ↔ 书写、举手 ↔ 扶额、讨论 ↔ 听讲

- **证据**：阅读 P 0.307 / 书写 P 0.421，两个低头类互相吞；举手 R 0.655（漏检主要来自"手没举过肩"）。
- **改良**：① 提高 `cls_pw`（0.35 → 0.5）与 `cls` gain；② 用混淆矩阵定位主导混淆对后，针对性补 200~300 张区分样本；
  ③ 引入"头部朝向 + 手部位置"的辅助监督（关键点模型或姿态估计分支），成本较高，列为长期项。

### P1-2 域差：训练数据来自外校/海外，本校场景未适配

- **证据**：数据集覆盖国内中小学（固定机位）+ 海外中学 + 国内高校，但**没有本校教室**；
  同一模型在不同机位/光照下指标会明显下降。
- **改良**：拍 300~500 张本校教室（含早晚光照、前后排、不同机位），用当前模型预标注 → 人工修正 → 微调 20~30 轮。

### P1-3 类别不均衡：听讲 11.7 万框 vs 趴桌 3 千框

- **证据**：最长/最短类实例比约 **39:1**。
- **现状**：已启用 `cls_pw=0.35` 类别加权 + 去重分组过采样，缓解但不解决。
- **改良**：稀有类继续补数据；或对稀有类单独训一个二分类器做"二次校验"。

### P2-1 系统层：实时性与跟踪稳定性

- **证据**：桌面端逐帧推理，640 输入在 RTX 5070 上约 30~60 FPS（单人会话），但多人密集场景跟踪 ID 会跳变，导致"逐学生行为时长"统计有误差。
- **改良**：① 改 `botsort.yaml` 并调 `track_high_thresh`/`match_thresh`；② 加 3~5 帧的多数投票平滑；
  ③ 视频检测按 2~3 帧抽检（精度损失小、速度 ×2~3）。

### P2-2 系统层：只有全局置信度阈值，没有按类阈值

- **证据**：全类共用 `conf=0.30`，导致讨论/阅读的误检混进统计，而趴桌/手机又偏保守。
- **改良**：在 `configs/app.yaml` 增加 `per_class_conf`，按类阈值（听讲 0.45、阅读/书写/讨论 0.55、趴桌/手机 0.35、举手/站立 0.40）。

### P2-3 系统层：预警只有阈值，没有跨帧确认

- **证据**：当前趴桌 8 秒 / 玩手机 5 秒触发，单帧误检会造成误报。
- **改良**：预警前要求"连续 N 帧同类 + 跟踪 ID 一致"（现有 tracking 已具备，只需在 `src/alerts.py` 加窗口计数）。

### P3-1 工程层：数据集重建耗时

- **证据**：42,695 张图重建一次约 35 分钟（dHash 哈希 + O(n²) 聚类 + 拷贝）。
- **改良**：哈希缓存到 `data/hash_cache.json`，二次构建只算新增图；聚类换 BK-tree，复杂度降到 O(n log n)。

### P3-2 工程层：8GB 显存限制模型规模

- **证据**：yolo11m @640 batch 4 已接近 8GB 上限，yolo11l/x 不可行。
- **改良**：正式训练租云 GPU（AutoDL 4090/24GB）跑 yolo11m/l；或蒸馏（大模型教师 → yolo11s 学生）。

## 三、改良路线（按投入产出比排序）

| 阶段 | 动作 | 预期收益 | 工作量 |
| --- | --- | --- | --- |
| **第 1 步** | 自采本校数据：趴桌/玩手机各 200~300 张，其余每类 50~100 张；用当前模型预标注 + 人工修正 | mAP50-95 **+3~6**，域内可用性质变 | 2~3 天（7 人） |
| **第 2 步** | 加按类阈值 + 预警跨帧确认 + 跟踪调参 | 误报率 **-40%**（主观观感提升明显） | 半天（纯代码） |
| **第 3 步** | imgsz 896 微调 20~30 轮（从 v5 暖启动） | mAP50-95 **+2~4**（小目标） | 5~6 小时（单机） |
| **第 4 步** | 清洗阅读/书写的组框，统一标注口径后重训 | 阅读/书写 mAP50 **+5~8** | 1 天清洗 + 6 小时训练 |
| **第 5 步** | 半监督：用当前模型标注新视频，人工只改错误帧 | 数据量 ×2 而人工成本 ×0.3 | 长期滚动 |
| 进阶 | 姿态/关键点辅助分支、分学段模型、云 GPU 训 yolo11m | +3~5 | 1~2 周 |

## 四、8GB 显存参数建议（RTX 5070 Laptop）

社区实测参考：`yolo11n@640 batch=16` 约 6~8GB，`yolo11s@640 batch=8` 约 8~10GB。

| 场景 | 模型 | imgsz | batch | 说明 |
| --- | --- | --- | --- | --- |
| 流程验证 | yolo11n | 320~640 | 16 | 先确认数据与代码没问题 |
| **正式训练（推荐）** | yolo11s | 640 | 8 | 精度/速度平衡；OOM 就降到 4 |
| 小目标（后排学生） | yolo11n | 960 | 4 | 人数多、目标小，加大输入尺寸 |
| 不推荐 | m / l / x | — | — | 8GB 显存放不下 |

其他要点：

* `amp: true`（默认开）省 30%~40% 显存，保持开启；
* Windows 下 `workers: 0~2`，设大了容易出 DataLoader 报错；
* `patience` 不要小于 15（相似行为收敛慢）；正式训练 150 轮左右；
* `fliplr: 0.5` 对「举手/转头」这类方向敏感类别有影响，如果发现左右手混淆严重可降到 0.2；
* 数据增强里 `mosaic: 1.0`、`mixup: 0.1`、HSV 三件套对课堂光照差异帮助最大。

## 七、常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| `no kernel image is available` | torch 版本太老，装 cu128 版本：`pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128` |
| CUDA out of memory | `--batch 4`、`--imgsz 512`，或把 `cache` 关掉（默认已关） |
| DataLoader worker 报错（Windows） | `workers: 0` |
| 训练 loss 正常但预测全是同一类 | 类别 id 与 `names` 顺序漂移：检查标注时的类别顺序是否与 `configs/classes.yaml` 一致 |
| 中文路径报错 | 本项目的 `src/utils.py` 已封装 `imread/imwrite` 处理中文路径；自己写脚本时不要直接用 `cv2.imread` |
| 部分类别 AP 极低 | 该类别样本太少（举手、玩手机）；用 `--oversample-min 300` 过采样 + 继续补数据 |
| 总 mAP 高但实际用起来不准 | 看混淆矩阵：阅读↔书写、听讲↔讨论 是课堂场景的主要混淆对，需要细化标注规则 |

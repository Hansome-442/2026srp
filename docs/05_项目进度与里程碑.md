## 五、阶段④ 模型验证与调试（2027.01—02）

按下面的顺序做，每一步都留记录（写进结题报告）：

1. **基线评估**：`scripts/val.py` 输出每类 P/R/mAP + 混淆矩阵，记录基线数字；
2. **数据侧优化**：补稀有类样本 → 过采样 → 重新训练，对比每类 AP（尤其举手、玩手机）；
3. **参数消融**：输入尺寸（640 vs 960）、模型规模（n/s）、增强开关（mosaic/mixup/fliplr）各做一组对比；
4. **业务指标验证**：在自建测试视频上统计「抬头率」与人工标注结果的偏差，评估预警误报/漏报率；
5. **部署验证**：ONNX 导出后在 CPU 与 GPU 上的 FPS、显存占用对比；
6. **达标线建议**：总体 mAP50 ≥ 0.85；每类 AP50 ≥ 0.7（稀有类 ≥ 0.6）；实时性 ≥ 15 FPS（640 尺寸）。

## 七、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 稀有类样本不足（举手、玩手机） | 该类 AP 极低，系统误报多 | 专项补采 + 过采样 + 提高该类阈值；必要时先合并为「其它」类，后期再拆 |
| 学段/场景分布不均 | 换教室后效果骤降 | 按覆盖矩阵采集；训练时按场景分组做交叉验证 |
| 标注一致性差 | 类别边界模糊，模型学不到规律 | 规范量化判定优先级；抽检 + 争议样本集体裁决 |
| 显存不足（8GB） | 训练中断 | batch 4 + imgsz 512；或租用云 GPU（AutoDL 等）跑正式训练 |
| 时间冲突（课程/考试） | 进度拖延 | 采集与标注解耦，标注任务可分片推进；每周组会盯 `dataset_stats.md` |
| 数据合规问题 | 无法公开发布 | 提前取得许可；人脸脱敏；仅发布标注文件 |

## 二、关键工程问题：数据泄漏（必须写进报告）

第一版模型在随机划分上得到 **mAP50 = 0.884**，但测试时效果对不上。用 dHash 感知哈希
（64 位差值哈希 + 汉明距离 ≤ 6 聚类）检查发现：

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 重复簇 | 1661 个（涉及 7833 张） | 1661 个 |
| **跨 train/val/test 重复** | **1038 簇 / 6313 张（39%）** | **0 簇 / 0 张** |

原因：SCB3 等数据集是**视频抽帧**，相邻帧几乎完全相同，随机划分把同一段视频拆到了
训练集和验证集两侧 → 验证指标虚高。

**修复方案**：`scripts/prepare_dataset.py` 默认开启「感知哈希去重分组 + 按来源/类别双层分层」：
同一重复组只能进同一个划分；每个来源在每个划分中都有样本。
另提供 `scripts/dataset_dedup.py` 做独立复检，输出 `reports/dataset_dedup.md`。

## 四、过拟合诊断（v2，100 轮）

用 `scripts/check_overfit.py` 自动诊断（依据：train/val 损失是否分叉、mAP 是否回落、
最后 10 轮 val loss 与最低值的比值）：

| 指标 | 数值 |
| --- | --- |
| train box_loss 近期变化 | -2.4% |
| val box_loss 近期变化 | +0.4% |
| val box_loss 最低值 / 最后 10 轮均值比 | ≈ 1.0 |
| mAP50-95 最好（轮次） | 0.481（第 100 轮附近） |
| **结论** | **曲线正常，未见过拟合；也不欠拟合** |

说明：v2 的 100 轮已收敛，**继续加轮次的收益小于加数据/调增强**。

## 五、第三版（v3）改进项（依据 ultralytics 官方配方 + 源码核实）

| 改进 | v2 | v3 | 依据 |
| --- | --- | --- | --- |
| 类别加权 | 无 | **cls_pw = 0.35** | 8.4.178 原生支持，按 (1/类别实例数)^p 归一化后乘到分类 BCE；比直接调 cls gain 稳，不会整体抬高误检 |
| 优化器 | auto | **SGD，lr0=0.01，momentum=0.937** | auto 在 >1e4 迭代时就是 SGD(0.01, 0.9)，显式写死更可控 |
| mosaic | 1.0 | 0.8 + **close_mosaic 15** | 官方推荐区间，末段关 mosaic 稳定收敛 |
| 多尺度 | 关 | **multi_scale 0.25** | 近乎免费的尺度鲁棒性提升 |
| mixup | 0.1 | 0.05 | 检测任务 mixup 过强会伤定位 |
| 权重衰减 | 0.0005 | 0.0005 | 有效值 = wd×batch×accum/nbs，保持官方推荐 |
| 早停 | patience 100 | **patience 30** | 官方 fitness=mAP50-95，30 轮无新高即可停 |

**踩过的坑（值得写进报告）**：`train.py` 原先用硬编码白名单过滤配置键，导致
`cls_pw`、`multi_scale`、`momentum` 被静默丢弃（日志里仍是默认值 0.0）。
已改为「除 data/model/project/name 外全部透传」，并用 1 轮冒烟验证参数确实生效。

## 六、后续可做（按投入产出比排序）

1. **补本校真实教室数据 300~500 张**（趴桌/玩手机各 200~300）：这是提升 `mAP50-95` 最直接的手段；
2. imgsz 640 → 896（batch 4）：后排小目标经验可涨 2~4 mAP，代价是训练时间翻倍；
3. 推理侧 TTA（`augment=True`）：+0.5~1.5 mAP，延迟 2~3 倍，适合离线评估而非实时；
4. 按类阈值：趴桌/玩手机单独降到 0.15~0.2，减少这类误报（需自写后处理）。

## 七、第三版（v3）结果与公平对比

数据扩充到 **23,935 张 / 365,472 框**（新增 SCB5-Discuss 864 图、SCB5-Handrise-Read-write 6864 图），
按 v3 参数训练 100 轮，实际在第 83 轮触发早停（best mAP50-95 出现在第 53 轮，patience=30）。
`scripts/check_overfit.py` 诊断：**曲线正常，未见过拟合**（train/val 损失同步下降，
最后 10 轮 val loss / 最低值 = 1.002）。

**⚠️ 关键：不同数据集的测试集不能直接比。** v2 与 v3 的划分不同，因此把两个模型都放到
**v3 的测试集**（991 张 / 7228 个实例）上重评，才是公平对比：

| 模型 | mAP50 | mAP50-95 |
| --- | --- | --- |
| v2（未加 SCB5 数据） | 0.620 | 0.418 |
| **v3（加数据 + cls_pw 等调参）** | **0.671** | **0.462** |
| 提升 | **+5.1** | **+4.4** |

同一测试集上的逐类对比（v3 vs v2，mAP50）：

| 类别 | v2 | v3 | 变化 |
| --- | --- | --- | --- |
| 抬头听讲 | 0.967 | 0.973 | +0.6 |
| 阅读看书 | 0.563 | 0.638 | **+7.5** |
| 书写记笔记 | 0.514 | 0.602 | **+8.8** |
| 举手发言 | 0.758 | 0.774 | +1.6 |
| 站立回答 | 0.726 | 0.742 | +1.6 |
| 小组讨论 | 0.289 | 0.393 | **+10.4** |
| 趴桌睡觉 | 0.545 | 0.567 | +2.2 |
| 玩手机 | 0.600 | 0.676 | **+7.6** |

**结论：v3 在全部 8 个类别上都优于 v2**，数据扩充与参数调优方向正确。最终指标（v3 测试集）：

- 总体 **mAP50 = 0.671，mAP50-95 = 0.462**
- 召回率 0.68~0.94（不漏人），精确率 0.35~0.88（误检集中在小组讨论）

### 本轮验证过的负结果（同样值得写进报告）

| 尝试 | 结果 | 说明 |
| --- | --- | --- |
| TTA（`augment=True`）评估 | mAP50 0.671 vs 0.671，**无提升** | 延迟翻倍无收益，不建议实时场景启用 |
| SCB5-Discuss 的标注口径 | 与主数据不一致：SCB5 框平均 0.21×0.29（一组人），STBD 框平均 0.15×0.15（单人） | 但加入后讨论类 mAP50 仍从 0.289 涨到 0.393，说明多场景数据净收益为正 |
| 早期「v3 比 v2 差」的直觉 | 错 | 那是拿不同测试集比，属测量口径错误——**报告里必须写清测试集版本** |

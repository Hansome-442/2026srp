## 1. 先决定：Git 仓库 还是 压缩包？

**结论：用 Git 仓库，别再用压缩包传来传去。**

理由很直接：

| | Git 仓库 | 压缩包 |
|---|---|---|
| 代码体积 | 约 1 MB | 每次全量 1 MB+ |
| 谁改了什么 | `git diff` 一眼看清 | 靠文件名猜 |
| 两个人同时改 | 自动合并或明确冲突 | 后发的人覆盖先发的人 |
| 回滚 | `git checkout` | 看谁还留着旧包 |
| 数据/权重 | 不进仓库（见第 3 节） | 每次塞进去，包越来越大 |

**但有一条铁律：数据和训练产物永远不进 Git。** 数据 26 GB、`runs/` 653 MB，塞进去仓库直接废掉。`.gitignore` 已经配好，照用即可。

仓库放哪，取决于成员能不能连 GitHub —— 见下一节。

### 1.1 先测，别假设「不能翻墙」

网页慢 ≠ clone 不了。让成员在自己机器上跑这一行：

```powershell
curl.exe -o NUL -w "%{http_code} %{time_total}s`n" -m 10 https://github.com
```

- 返回 **200 且 3 秒内** → 直接给 GitHub 地址，多数情况够用（GitHub 在国内是「慢」，不是「死」）
- 超时 / 连接重置 / 一直转圈 → 按下面三档走

| 档 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **1** | **SSH over 443**（走 GitHub 的备用端口） | 改 3 行配置 | 只是 22 端口被墙的情况，成功率最高 |
| **2** | **共享盘 bare 仓库** | 零账号、零翻墙 | 7 人全在国内、有校内网盘/共享盘 |
| **3** | **Gitee 镜像** | 要注册新号 | 想要网页端 Issue/PR |

**档 1：SSH over 443**

把 `C:\Users\<你>\.ssh\config` 改成：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```

然后 `ssh -T git@github.com`，看到 `Hi <用户名>! You've successfully authenticated` 就成了。
这条路实测可用：**它绕开了被墙的 22 端口，走的 443**。

**档 2：共享盘 bare 仓库（零依赖）**

仓库里已经配好一个远程 `share`，指向 `E:\2026srp-share.git`（1.2 MB 的裸仓库）。

```bash
# 你（负责人）：把这个文件夹整个拷到共享盘/校内网盘，路径例如 Z:\git\2026srp-share.git
git remote set-url share Z:/git/2026srp-share.git
git push share main

# 成员
git clone Z:/git/2026srp-share.git 2026srp
```

优点：不需要任何账号、速度是局域网/网盘的速度、7 人也不限人数。
缺点：没有 Issue/PR，两人同时改同一文件仍需手动合并（但 git 会告诉你冲突在哪，比压缩包强得多）。

**档 3：Gitee —— 注意人数限制**

Gitee 官方配额：**公有仓库成员数不限，但个人账号下所有私有仓库的协作人数合计只有 5 人**。
你们是 7 人，所以免费私有仓库**不够用**，只有三条路：代码公开、买企业版、或者用档 2。

### 1.2 本仓库当前的远程配置

| 远程 | 地址 | 用途 |
|---|---|---|
| `share` | `E:\2026srp-share.git` | 共享盘裸仓库（成员入口，离线可用） |
| `github` | 待填 `git@github.com:<你的账号>/2026srp.git` | 备份 / 公开展示 |

日常只需要两条命令同步：

```bash
git push share main          # 给成员
git push github main         # 备份到 GitHub（能连上的时候）
```

## 2. 装环境

### 2.1 先看你的显卡

| 你的显卡 | torch 安装方式 |
|---|---|
| RTX 50 系（5060/5070/5080/5090） | **必须 cu128 及以上**（Blackwell 架构，cu121 装不上） |
| RTX 40/30 系 | cu121 或 cu128 都行 |
| 只有核显 / 没 NVIDIA 卡 | 装 CPU 版，能跑界面，训练会慢 20 倍以上 |

### 2.2 路线 A：conda（推荐，最省事）

```bash
# 1) 装 Miniconda（略），然后在项目根目录执行：
conda env create -f environment.yml
conda activate classroom

# 2) 关键一步：torch 要单独确认是 GPU 版
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#    期望输出类似：2.7.1+cu128 True
#    如果是 False 或没有 +cuXXX，重装：
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

### 2.3 路线 B：pip（已有 Python 3.11 的话）

```bash
python -m venv .venv
.venv\Scripts\activate

# 先单独装 torch（一定要带 index-url，否则拉到 CPU 版）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

# 再装其余精确版本（83 个包，已锁死版本号）
pip install -r requirements.lock.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2.4 验证：一条命令

```bash
python scripts/check_env.py
```

全部 ✅ 才算装好。它会检查 14 个包、GPU 算力、配置与数据目录，并告诉你缺什么。
看到 ❌ 不要往下走，先按它最后三行的提示修。

> 本机基准（`E:\2026srp`，作为对照）：Python 3.11.15 / torch 2.7.1+cu128 /
> ultralytics 8.4.178 / RTX 5070 Laptop 8 GB / CUDA 12.8。

## 3. 拿数据（不进仓库，单独传）

数据总量 **26 GB**，分成三块：

| 目录 | 内容 | 要不要拿 |
|---|---|---|

传法：移动硬盘 / 学校网盘 / 阿里云盘，**别用微信QQ**（会压坏）。

放好之后目录应该长这样：

```
E:\2026srp\data\
├── dataset.yaml                 ← 训练入口，必须存在
├── processed\
│   ├── images\{train,val,test}\
│   └── labels\{train,val,test}\
└── raw\                         ← 只在你要重建数据集时才需要
```

> 如果只拿到 `raw`，跑 `python scripts/prepare_dataset.py --voc-dir data\raw\classroom_voc`

## 6. 下一步工作重心（按投入产出比排序）

这是接手的重点。**从上往下领，不要跳。**

### P0：把「换教室就掉点」解决掉 —— 自采本校数据

**为什么最急**：现有 46,760 张全部来自外校/海外，没有一张本校教室。
论文里叫「域差」，实测换机位/换光照就掉 10~20 个点。

| 做什么 | 量 | 谁 |
|---|---|---|
| 自采本校教室：不同机位、早晚光照、前后排 | 300~500 张 | 数据组（2 人，2 天） |
| 重点补稀有类：趴桌睡觉、玩手机 | 各 200~300 张 | 数据组 |
| 用当前 `runs/best.pt` 预标注 → 人工修正 | — | 数据组 |
| 微调 20~30 轮 | — | 算法组 |

**验收**：本校 test 集上趴桌/玩手机 mAP50 ≥ 0.70 / 0.80。

### P0：统一标注口径（阅读 / 书写 / 小组讨论）

**问题**：`docs/08` 里量过——SCB5 的 discuss 框是「一组人」（0.214×0.291），
STBD-08 是「单人」（0.152×0.154），两种习惯混在一起训练，模型学不到稳定特征。

**做什么**：
1. 按 `docs/02_八类定义与标注规范.md` 定死：**一人一框，禁止组框**
2. 写脚本把框面积 > 均值 2σ 的组框剔掉或拆分
3. 清洗后重训，对比阅读/讨论的 mAP50（预期 +5~8）

### P1：系统层三件小事（纯代码，半天见效）

| 事项 | 改哪里 | 收益 |
|---|---|---|
| 按类阈值（已有 `per_class_conf`，只是没调优） | `configs/app.yaml` | 误报 -30% |
| 预警加跨帧确认（连续 N 帧同类 + 同 track_id） | `src/alerts.py` | 误报 -40% |
| 跟踪调参（`track_high_thresh` / `match_thresh`） | `src/tracker.py` | ID 跳变减少 |

这三件**不需要重训模型**，投入产出比最高，适合刚接手的同学练手。

### P1：imgsz 896 微调（小目标）

从当前 `best.pt` 暖启动，`--imgsz 896 --epochs 25`。
后排学生从 30~50 px 变成 45~75 px，预期 mAP50-95 +2~4，代价是训练时长 ×2。

### P2：长期项（有余力再做）

- 姿态/关键点辅助分支（区分「阅读 vs 书写」最有效，但成本高）
- 半自动标注：用当前模型标新视频，人工只改错帧
- 云 GPU 训 yolo11m（8 GB 显存跑不动 m/l）

## 7. 排错表

| 症状 | 原因 | 解决 |
|---|---|---|
| `torch.cuda.is_available()` 是 False | 装成 CPU 版 torch | 用 `--index-url .../cu128` 重装 |
| `no kernel image is available` | torch 版本低于显卡架构 | 50 系必须 cu128+ |
| `CUDA out of memory` | batch 太大 | `--batch 4`，或 `--imgsz 512` |
| `DataLoader worker exited` | Windows 多进程问题 | `configs/train.yaml` 里 `workers: 0` |
| 界面能开但一个框都没有 | 权重不对（回退到 COCO yolo11n） | 确认 `runs/best.pt` 存在；`configs/app.yaml` 的 `weights` 指向它 |
| 中文标签显示成方块 | 缺微软雅黑 | 装 `msyh.ttc`（Win 自带），或改 `src/detector.py` 的字体候选 |
| `ModuleNotFoundError: src` | 不在项目根目录执行 | `cd` 到项目根再跑 |
| 数据加载报 `No labels found` | `data/dataset.yaml` 路径不对 | 检查 yaml 里的 `path:` 是否为绝对路径 |
| 训练 loss 是 nan | 学习率/数据异常 | 加 `--no-amp` 试，检查标签是否越界 |
| 视频很卡 | 逐帧推理 + 画框 | 调小 `imgsz`、或调大抽帧间隔 |

## 8. 协作规矩

1. **别提交**：`data/`、`runs/`、`*.pt`、`reports/*.png`、`notes/sessions/`（`.gitignore` 已挡，别用 `git add -f` 硬塞）
2. **分支**：`main` 只放能跑的版本；自己开 `feature/xxx`、`fix/xxx`
3. **提交信息**：说清「改了什么 + 为什么」，例如 `fix: 预警加连续3帧确认，减少趴桌误报`
4. **改配置要写注释**：`configs/*.yaml` 里的数字后面注明依据，避免下一个人不知道为什么是 0.35
5. **跑完训练先提交报告**：`reports/val_report_*.md` 进仓库；权重 `*.pt` 不进仓库，放网盘并在组里留链接
6. **每周组会前**：`python scripts/check_env.py` + 更新 `reports/dataset_stats.md`
